# `@tetherto/mdk-worker` — Consolidate Base Classes & Utilities

> **Version:** 0.2.0  |  **Date:** 2026-07-01  |  **Status:** Design — awaiting §002 workspace imports rollout
> **Audience:** Developers working in `mdk-prv`
> **Depends on:** `[002.npm-workspace-imports.md](./002.npm-workspace-imports.md)` — workspace import pattern must be in place first.

---

## Problem

Every device type has its own `base/` package in `backend/workers/`, each separately installed and currently named under a `@tetherto/tpl-lib-*` scheme that does not match the  heirachy of libraries. 

On top of that, stat utilities live in a completely separate `backend/core/lib-stats/` with no `package.json` at all, forcing every worker to reach them via deep relative paths.

### Current state


| Device type        | Base package path                  | Current package name           | Main exports                                    |
| ------------------ | ---------------------------------- | ------------------------------ | ----------------------------------------------- |
| Generic worker     | `backend/workers/base`             | `@tetherto/tpl-lib-thing`      | `Thing`, `ThingManager`                         |
| Miner              | `backend/workers/miners/base`      | `@tetherto/tpl-lib-miner`      | `Miner`, `MinerManager`                         |
| Container          | `backend/workers/containers/base`  | `@tetherto/tpl-lib-container`  | `Container`, `ContainerManager`                 |
| Miner pool         | `backend/workers/minerpools/base`  | `@tetherto/tpl-lib-minerpool`  | `MinerPoolManager`                              |
| Power meter        | `backend/workers/power-meter/base` | `@tetherto/tpl-lib-powermeter` | `PowerMeter`, `PowerMeterManager`               |
| Temperature sensor | `backend/workers/temperature/base` | `@tetherto/tpl-lib-sensor`     | `Sensor`, `SensorManager`                       |
| Stat utilities     | `backend/core/lib-stats/`          | *(no package.json)*            | `applyStats`, `tallyStats`, `getVal`, `groupBy` |


Problems:

- Six separate packages that all represent "the base layer for a worker type" — no single dependency a device worker can declare.
- `@tetherto/tpl-lib-*` naming does not match the canonical `@tetherto/mdk-worker` name from DOC-HIERARCHY.
- `lib-stats` has no `package.json`, forcing every worker to reach it with paths like `require('../../../../../core/lib-stats/utils')`.

---

## Target State

One package — `@tetherto/mdk-worker` — that a worker declares as its single dependency to get all base classes and stat utilities:

```text
backend/workers/base/               # promoted and renamed to @tetherto/mdk-worker
├── package.json                    # name: "@tetherto/mdk-worker"
├── README.md
├── index.js                        # Thing, ThingManager (root base)
│
├── miner/
│   └── index.js                    # Miner (extends Thing), MinerManager (extends ThingManager)
├── container/
│   └── index.js                    # Container, ContainerManager
├── minerpool/
│   └── index.js                    # MinerPoolManager
├── powermeter/
│   └── index.js                    # PowerMeter, PowerMeterManager
├── sensor/
│   └── index.js                    # Sensor, SensorManager
│
└── utils/
    ├── index.js                    # re-exports all below
    ├── stats.js                    # applyStats, tallyStats, defaults (from lib-stats/index.js)
    ├── helpers.js                  # getVal, groupBy (from lib-stats/utils.js)
    └── ops/                        # stat operation implementations (from lib-stats/ops/)
```



### Public API

```js
// root base classes
const { Thing, ThingManager } = require('@tetherto/mdk-worker')

// device-type base classes
const { Miner, MinerManager }               = require('@tetherto/mdk-worker/miner')
const { Container, ContainerManager }       = require('@tetherto/mdk-worker/container')
const { MinerPoolManager }                  = require('@tetherto/mdk-worker/minerpool')
const { PowerMeter, PowerMeterManager }     = require('@tetherto/mdk-worker/powermeter')
const { Sensor, SensorManager }             = require('@tetherto/mdk-worker/sensor')

// stat utilities
const { applyStats, tallyStats, defaults }  = require('@tetherto/mdk-worker/utils')
const { getVal, groupBy }                   = require('@tetherto/mdk-worker/utils')
```



### Dependency direction

```text
@tetherto/mdk-worker  ←  @tetherto/mdk-worker-whatsminer
                      ←  @tetherto/mdk-worker-antminer
                      ←  @tetherto/mdk-worker-<container>
                      ←  @tetherto/mdk-worker-<minerpool>
                      ←  @tetherto/mdk-worker-<powermeter>
                      ←  @tetherto/mdk-worker-<sensor>
```

## How a Device Worker Changes

A device worker today:

```js
// backend/workers/miners/whatsminer/lib/miner.manager.js
const MinerManager = require('../../../base/lib/miner.manager')
const { getVal } = require('../../../../../core/lib-stats/utils')
const { applyStats } = require('../../../../../core/lib-stats')
```

After:

```js
// backend/workers/miners/whatsminer/lib/miner.manager.js
const { MinerManager } = require('@tetherto/mdk-worker/miner')
const { getVal, applyStats } = require('@tetherto/mdk-worker/utils')
```

Device worker `package.json`:

```json
{
  "name": "@tetherto/mdk-worker-whatsminer",
  "dependencies": {
    "@tetherto/mdk-worker": "^0.3.0"
  }
}
```

## Acceptance Criteria

- `rg "require.*tpl-lib-(thing|miner|container|minerpool|powermeter|sensor)"` returns zero matches.
- `rg "require.*core/lib-stats"` returns zero matches.
- `rg "require.*workers/(miners|containers|minerpools|power-meter|temperature)/base"` returns zero matches.
- All device worker tests pass (`npm test --workspaces`).
