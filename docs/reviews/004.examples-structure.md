# `mdk-prv` — Examples Structure (Two-Tier)

> **Version:** 0.1.0  |  **Date:** 2026-06-30  |  **Status:** Design
> **Audience:** Developers working in `mdk-prv`
> **Depends on:** [`002.npm-workspace-imports.md`](./002.npm-workspace-imports.md) — named imports must be in place before migrating examples.

---

## Problem

Examples currently live in two overlapping locations with no consistent rule for which belongs where:

```text
mdk-prv/
├── examples/
│   ├── backend/         # mix of per-package snippets and full-stack demos
│   │   ├── ork/         # ORK-only flows
│   │   ├── miners/      # single-worker snippets
│   │   ├── site/        # multi-service, cross-package
│   │   ├── site-single-process/  # cross-package orchestration example
│   │   ├── mdk-e2e/     # full e2e flow
│   │   └── ...
│   ├── full-site/       # another full-stack demo
│   ├── e2e/
│   └── ui-client/
```

Problems:
- No distinction between "run the full system" and "show one package API."
- Cross-package imports via relative paths (`../../../workers/...`) — violates §002.
- No index / README telling a new developer where to start.
- CI does not run any examples — breakage is discovered manually.

---

## Target State — Two Tiers

### Tier A — Full-stack runnable apps (`examples/`)

**Purpose:** Cross-package demos that wire Kernel + Gateway + Workers together. Show the whole system running. Intended as the first thing a new developer runs.

**Rules:**
- Each Tier A example is its own workspace package with a `package.json`.
- Declares workspace deps on `@tetherto/mdk-core`, `@tetherto/mdk-worker`, device worker packages, etc. — no relative `../../../` imports.
- Ships a `README.md` with: prerequisites, config, `npm start`, expected output, ports used.
- Runnable from repo root: `npm start --workspace examples/site-single-process`.

**Target layout:**

```text
mdk-prv/
└── examples/
    ├── README.md                       # index: what each example does, ports, prerequisites
    ├── site-single-process/            # ORK + Gateway + workers in one process (already migrated — §002 PoC)
    │   ├── package.json                # deps: @tetherto/mdk-core, @tetherto/mdk-worker-*
    │   ├── index.js
    │   └── config/
    ├── full-site/                      # ORK + Gateway + workers multi-process
    │   ├── package.json
    │   ├── start.js
    │   └── backend/
    └── e2e/                            # automated end-to-end flow
        ├── package.json
        └── ...
```

### Tier B — Per-package snippets (live beside the package they document)

**Purpose:** Minimal scripts that exercise **one** published package. Linked from that package's `README.md`. Copy-paste starting points for integrators.

**Rules:**
- Lives inside the package it documents: `packages/core/ork/examples/`, `packages/workers/miners/whatsminer/examples/`, etc.
- Runnable from the package root: `node examples/telemetry-flow.js`.
- Imports only from that package's own public API (`main` / documented exports) plus declared workspace deps — no imports from sibling packages via relative paths.
- Documents the port it uses in a comment at the top of the file. No port collisions across Tier B examples in the same vertical.

**Target layout:**

```text
packages/
├── core/
│   ├── ork/examples/                  # Kernel-only: telemetry-flow, ork-shell, auth-whitelist
│   ├── client/examples/               # Client-only connection samples
│   └── app-node/examples/             # Gateway smoke test (optional)
└── workers/
    ├── miners/
    │   ├── whatsminer/examples/        # single Whatsminer worker + mock server
    │   └── antminer/examples/          # single Antminer worker + mock server
    ├── containers/examples/
    ├── power-meter/examples/
    └── temperature/examples/
```

## Migration Steps

1. Audit `examples/backend/` — classify each file as Tier A (cross-package) or Tier B (single-package).
2. Move Tier B files into their owning package's `examples/` directory.
3. Move Tier A files into the top-level `examples/` directory with a proper `package.json`.
4. Add each Tier A example to root `"workspaces"` in `package.json`.
5. Replace all relative cross-package `require` calls with scoped names (§002).
6. Write or update `README.md` for each Tier A example.
7. Link each Tier B example from the owning package's `README.md`.
8. Delete `examples/backend/` once empty.

- Every Tier A example has a `README.md` and a `package.json` with named deps.
- Every Tier B example is linked from the package `README.md` it documents.
- `rg "require.*\.\./\.\./\.\./workers"` returns zero matches inside `examples/`.
- CI smoke job runs at least one Tier A example successfully.
